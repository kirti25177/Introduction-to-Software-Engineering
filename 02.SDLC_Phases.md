# Software Development Life Cycle (SDLC) Phases

## 1. What Is SDLC?

SDLC stands for **Software Development Life Cycle**.

It is a step-by-step process used to develop software, from the initial idea to maintenance.

**Main phases of SDLC:**

Planning → Requirement Analysis → Design → Implementation → Testing → Deployment → Maintenance

## 2. Phases of SDLC

### 1. Planning

In this phase, the team decides what software to build and why it is needed.

**Activities:**
- Define the problem.
- Set project goals.
- Estimate time and cost.
- Check whether the project is possible.

**Example:** A college decides to build an online attendance system.

### 2. Requirement Analysis

In this phase, the team understands what users need from the software.

Requirements describe the features and functions the software must provide.

**Activities:**
- Talk to users.
- Identify required features.
- Understand user expectations.
- Document the requirements.

**Example:** Teachers should be able to mark attendance, and students should be able to view their attendance records.

### 3. Design

In this phase, the team plans how the software will be built.

**Activities:**
- Design the user interface.
- Plan the database.
- Decide the system structure.
- Choose suitable technologies.

**Example:** The team designs the login page, attendance page, and student database.

### 4. Implementation

Implementation means writing the code to build the software.

Developers convert the design into a working application.

**Activities:**
- Write code.
- Create different features.
- Connect the database.
- Integrate different components.

**Example:** Developers write code to allow teachers to mark attendance.

### 5. Testing

In this phase, the software is checked to find errors and make sure it works correctly.

**Activities:**
- Find and report bugs.
- Check different features.
- Verify requirements.
- Fix errors and test again.

**Example:** The team checks whether attendance is saved correctly and whether students can view their records.

### 6. Deployment

Deployment means making the software available for users.

**Activities:**
- Install or publish the application.
- Configure the production environment.
- Make the system accessible to users.

**Example:** The college launches the attendance system for teachers and students.

### 7. Maintenance

Maintenance takes place after the software has been released.

The team fixes problems and makes improvements when needed.

**Activities:**
- Fix bugs.
- Improve existing features.
- Add new features.
- Update the software for changing needs.

**Example:** The team fixes an issue that prevents some students from viewing their attendance.

## 3. Summary Table

| Phase | Main Purpose |
|---|---|
| Planning | Decide what to build |
| Requirement Analysis | Understand what users need |
| Design | Plan how to build it |
| Implementation | Write the code |
| Testing | Find and fix errors |
| Deployment | Release the software |
| Maintenance | Fix and improve the software |

## 4. Why Are SDLC Phases Important?

- They organize the development process.
- They help teams understand their responsibilities.
- They make project progress easier to track.
- They help identify problems earlier.
- They improve software quality.

**Note:** In some development models, these phases may overlap or repeat instead of following a strict sequence.

## 5. Key Takeaways

- SDLC provides a structured way to develop software.
- Each phase has a specific purpose.
- Testing checks whether the software works correctly.
- Deployment makes the software available to users.
- Maintenance continues after release.
