# Software Development Life Cycle (SDLC) Models

## 1. What Is an SDLC Model?

An SDLC model describes how the different phases of software development are organized and performed.

Different models are suitable for different projects.

## 2. Waterfall Model

The Waterfall Model follows a step-by-step approach. One phase is generally completed before the next phase begins.

**Flow:**

Planning → Requirements → Design → Coding → Testing → Deployment → Maintenance

**Advantages:**
- Simple and easy to understand.
- Easy to manage when requirements are clear.
- Each phase has defined goals.

**Disadvantages:**
- Changes are difficult to handle later.
- Testing usually happens after development.
- Not suitable when requirements change frequently.

**Example:** A small project with clearly defined requirements.

## 3. Iterative Model

In the Iterative Model, software is developed and improved through repeated cycles.

Each cycle adds improvements based on the previous version.

**Advantages:**
- Allows regular improvements.
- Feedback can be used in later cycles.
- Problems can be identified early.

**Disadvantages:**
- Repeated changes may increase cost.
- Requires regular evaluation and planning.

**Example:** Improving an existing application based on user feedback.

## 4. Incremental Model

In the Incremental Model, software is developed and delivered in smaller functional parts called increments.

Each increment adds new features.

**Advantages:**
- Useful features can be delivered early.
- Easier to test smaller parts.
- Progress is visible after each increment.

**Disadvantages:**
- Requires good planning and design.
- Integrating different parts can be challenging.

**Example:** A college application that first provides login, then attendance, and later examination results.

## 5. Spiral Model

The Spiral Model develops software through repeated cycles, with special attention to identifying and managing risks.

Each cycle usually includes planning, risk analysis, development, and evaluation.

**Advantages:**
- Focuses on risk management.
- Supports changes during development.
- Suitable for complex projects.

**Disadvantages:**
- Can be expensive.
- Requires expertise in risk analysis.
- May be too complex for small projects.

**Example:** A large banking system where security and project risks must be carefully managed.

## 6. V-Model

The V-Model is a development model in which testing activities are planned alongside corresponding development phases.

It is called the V-Model because its phases are often shown in a V-shaped diagram.

**Advantages:**
- Testing is planned early.
- Requirements can be checked systematically.
- Suitable for projects with clear requirements.

**Disadvantages:**
- Changes can be difficult to manage.
- Less flexible when requirements change frequently.

**Example:** Software for systems where reliability and verification are especially important.

## 7. Prototype Model

The Prototype Model involves creating an early sample of the software called a **prototype**. Users review it and provide feedback before the final software is developed.

**Steps:**

1. Gather basic requirements.
2. Create a prototype.
3. Get feedback from users.
4. Improve the prototype based on feedback.
5. Develop and test the final software.

**Advantages:**
- Helps clarify unclear requirements.
- Users can see and try an early version.
- Feedback helps improve the software design.

**Disadvantages:**
- Repeated changes can increase development time and cost.
- Users may mistake the prototype for the final product.
- Poor planning may lead to design problems.

**Example:** Creating a sample design of a college website so students and teachers can review its layout before full development.

## 8. Agile Model

Agile is an approach in which software is developed in small cycles with frequent feedback and improvements.

Teams collaborate with stakeholders and adapt to changing requirements.

**Advantages:**
- Handles changing requirements well.
- Delivers working software frequently.
- Encourages teamwork and feedback.

**Disadvantages:**
- Requires regular communication.
- Frequent changes can affect planning.
- The final timeline may be harder to predict.

**Example:** Developing an online shopping application and releasing new features regularly.

## 9. Comparison of SDLC Models

| Model | Main Feature | Best Suited For |
|---|---|---|
| Waterfall | Sequential phases | Stable requirements |
| Iterative | Repeated improvements | Software that evolves over time |
| Incremental | Delivery in smaller parts | Projects needing early features |
| Spiral | Risk analysis in each cycle | Complex, high-risk projects |
| V-Model | Development linked with testing | Projects with clear requirements and strong verification needs |
| Prototype | Early sample and user feedback | Projects with unclear requirements |
| Agile | Frequent feedback and adaptation | Projects with changing requirements |

## 10. How to Choose an SDLC Model?

The choice depends on:

- Whether requirements are clear or changing.
- Project size and complexity.
- Budget and available time.
- Project risks.
- Customer involvement.
- Testing and quality requirements.

No single model is best for every project.

## 11. Key Takeaways

- The Waterfall Model follows a sequential approach.
- The Iterative Model improves software through repeated cycles.
- The Incremental Model delivers software in parts.
- The Spiral Model focuses on risks.
- The V-Model connects development and testing activities.
- The Prototype Model uses an early sample to gather feedback.
- Agile emphasizes collaboration, feedback, and adaptability.
