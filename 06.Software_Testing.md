# Software Testing

## 1. What Is Software Testing?

Software testing is the process of checking software to find errors and make sure it works as expected.

**Example:** Testing a login page to check whether users can log in with the correct password.

## 2. Why Is Software Testing Important?

- Helps find bugs and errors.
- Improves software quality.
- Checks whether requirements are met.
- Improves security and reliability.
- Helps provide a better user experience.

## 3. What Is a Bug?

A bug is an error or defect in software that causes it to behave incorrectly.

**Example:** A calculator displays `10` instead of `5` when adding `2 + 3`.

## 4. Types of Software Testing

### 1. Manual Testing

Testing performed by a person without using test automation scripts.

**Example:** A tester manually enters login details to check the login page.

### 2. Automation Testing

Testing performed using scripts and tools to execute test cases automatically.

**Example:** A script automatically checks whether a login page works correctly.

## 5. Levels of Software Testing

### 1. Unit Testing

Tests a small part of the software, such as a function or method.

**Example:** Testing a function that adds two numbers.

### 2. Integration Testing

Checks whether different modules work correctly together.

**Example:** Checking whether the login page communicates correctly with the database.

### 3. System Testing

Tests the complete software system.

**Example:** Testing all major features of a college management application.

### 4. Acceptance Testing

Checks whether the software meets user or business requirements.

**Example:** College staff check whether the attendance system meets their needs before approving it.

## 6. Black-Box vs. White-Box Testing

| Black-Box Testing | White-Box Testing |
|---|---|
| Tests software behavior without examining internal code. | Tests internal code and logic. |
| Focuses on inputs and outputs. | Focuses on code paths and conditions. |
| Example: Checking login with valid and invalid passwords. | Example: Checking different branches inside a login function. |

## 7. Verification vs. Validation

- **Verification:** Are we building the software correctly according to its specifications?
- **Validation:** Are we building the right software for the user's needs?

**Example:**
- Verification checks whether a feature follows its design.
- Validation checks whether the feature solves the user's actual problem.

## 8. What Is a Test Case?

A test case is a set of steps, inputs, and expected results used to check a software feature.

**Example: Login Test Case**

| Item | Details |
|---|---|
| Test | Login with correct credentials |
| Input | Valid username and password |
| Expected Result | User logs in successfully |

## 9. What Is Regression Testing?

Regression testing checks that existing features still work after changes are made to the software.

**Example:** After updating the login page, testing it again to ensure login still works correctly.

## 10. Key Takeaways

- Software testing checks whether software works as expected.
- A bug is an error or defect in software.
- Manual testing is performed by a person; automation testing uses scripts and tools.
- Unit testing checks small components.
- Integration testing checks interactions between modules.
- System testing checks the complete system.
- Acceptance testing checks whether user requirements are met.
- Regression testing checks that changes have not broken existing features.
