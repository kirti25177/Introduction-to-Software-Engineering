# Software Requirements

## 1. What Are Software Requirements?

Software requirements describe what a software system should do and how it should work.

They explain the needs and expectations of users.

**Example:** In a college attendance system, teachers should be able to mark attendance, and students should be able to view their attendance records.

## 2. Types of Software Requirements

Software requirements are mainly divided into two types:

1. Functional Requirements
2. Non-Functional Requirements

## 3. Functional Requirements

Functional requirements describe **what the software should do**.

They define the features and functions of a system.

**Examples:**
- Users can log in using their credentials.
- Students can view attendance records.
- Teachers can mark attendance.
- Users can reset their passwords.
- Administrators can manage student accounts.

## 4. Non-Functional Requirements

Non-functional requirements describe **how well the software should work**.

They define the quality and performance of a system.

**Examples:**
- **Performance:** Pages should load quickly.
- **Security:** Passwords must be protected.
- **Reliability:** The system should work consistently.
- **Usability:** The application should be easy to use.
- **Scalability:** The system should support more users as it grows.

## 5. Functional vs. Non-Functional Requirements

| Functional Requirements | Non-Functional Requirements |
|---|---|
| Describe what the system does. | Describe how well the system works. |
| Focus on features and operations. | Focus on quality and performance. |
| Example: A user can log in. | Example: Login should complete within two seconds under specified conditions. |

## 6. What Is Requirement Gathering?

Requirement gathering is the process of collecting information about what users need from a software system.

Common techniques include:

- **Interviews:** Asking users questions directly.
- **Questionnaires:** Collecting answers through forms.
- **Observation:** Watching how users perform their tasks.
- **Meetings:** Discussing requirements with stakeholders.
- **Document Analysis:** Studying existing documents and systems.

## 7. What Is SRS?

SRS stands for **Software Requirements Specification**.

It is a document that describes the requirements of a software system in a clear and organized way.

An SRS commonly includes:

- Purpose and scope of the software.
- Functional requirements.
- Non-functional requirements.
- System constraints.
- External interfaces.

**Example:** An SRS for a college attendance system describes login, attendance marking, reports, security, and performance requirements.

## 8. Characteristics of Good Requirements

Good software requirements should be:

- **Clear:** Easy to understand.
- **Complete:** Include all necessary information.
- **Consistent:** Do not contradict one another.
- **Testable:** Can be checked or verified.
- **Feasible:** Can be implemented with available resources.
- **Unambiguous:** Have only one reasonable interpretation.

## 9. Why Are Software Requirements Important?

- Help developers understand what to build.
- Reduce misunderstandings between users and developers.
- Help estimate time and cost.
- Guide software design and testing.
- Reduce costly changes caused by unclear requirements.

## 10. Key Takeaways

- Software requirements describe the needs of a software system.
- Functional requirements define what the system does.
- Non-functional requirements define how well it works.
- Requirement gathering helps identify user needs.
- SRS documents requirements in an organized format.
- Clear requirements help developers build the correct software.
